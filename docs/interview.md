# StockRadar 面试讲稿

## 项目定位

StockRadar 是一个 A股事件雷达 App。它接入沪深北全量股票池，针对 5000+ 股票生成异动信号，并通过 dashboard 展示市场结构、热门异动、自选监控和个股画像。

项目重点不是荐股，而是做“金融数据工程 + 后端 API + 前端可视化 + 异动分析”。

## 为什么做这个

普通股票项目往往只是展示 K 线和列表，技术深度不明显。这个项目选择“异动识别”作为核心问题，因为它需要处理：

- 全量股票数据同步
- 数据清洗和字段标准化
- 多指标排序和过滤
- 异动规则设计
- 前后端接口分层
- 高密度 dashboard 交互

## 架构

```text
东方财富公开行情
  -> scripts/sync-a-shares.js
  -> data/all-a-shares.json
  -> server.js API
  -> public/app.js dashboard
```

当前版本为了面试展示和本地稳定性，采用零依赖 Node 服务。后续生产化可以迁移到：

```text
定时任务 -> PostgreSQL -> Redis -> API 服务 -> Web 前端
```

## 核心数据模型

```text
code        股票代码
name        股票名称
exchange    SH / SZ / BJ
board       沪市主板 / 深市主板 / 创业板 / 科创板 / 北交所
price       最新价
changePct   涨跌幅
amount      成交额
turnover    换手率
marketCap   总市值
```

## 异动识别

异动分不是机器学习模型，而是一个可解释的规则分：

```text
score =
  abs(changePct) * 2.2
  + turnover * 0.9
  + log10(amount) * 0.7
  - marketCapPenalty
```

这样设计的原因：

- 涨跌幅体现价格异动
- 换手率体现筹码交换
- 成交额体现市场关注
- 市值惩罚避免大市值股票天然占优

## 可以被问到的问题

### 为什么不用预测模型？

因为面试项目里直接预测涨跌容易变成不可验证的黑盒。我选择做事件雷达，强调可解释、可复现和风险边界。系统输出的是“值得关注的异动”，不是买卖建议。

### 为什么用 JSON 而不是数据库？

MVP 阶段优先保证可运行和可演示。数据同步和 API 已经分层，后续把 JSON 替换为 PostgreSQL 不影响前端接口。

### 怎么支持 5000+ 股票？

同步脚本一次性拉取全量股票池，服务端做缓存，前端分页加载。当前每次默认只返回 100 条，避免一次渲染全部数据造成页面卡顿。

### 怎么生产化？

- 用 cron 或队列定时同步行情
- PostgreSQL 存储每日快照
- Redis 缓存市场概览和热门榜
- 接入公告、新闻和龙虎榜数据
- 对新闻做实体识别，关联股票代码
- WebSocket 推送自选股异动
- 增加用户系统和权限
